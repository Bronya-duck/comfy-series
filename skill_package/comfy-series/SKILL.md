# Comfy Series

在当前 Codex 中完成创作判断与实际看图。本地 Python 工具负责素材、模型、工作流、执行、预算和记录；没有另一个后台聊天大模型。用户已授权自动选择和下载公开免费模型、运行和自检，按每个系列累计最多30GB新增下载、每张最多三轮。切换风格先询问旧模型保留或删除；具体文件删除须获得用户确认。

## 每次调用的第一步：展示输出规格与填写格式

每次显式或隐式调用本技能，第一条用户可见回复先展示输出格式、精确宽高、画面比例、数量和风格控制，并区分用户已给出的值与默认值。完成这一步后，再检查环境、读取制作素材、选模型、下载或生成。必要的技能文件读取可先完成。

用户只说“测试”“开始”，或制作内容尚未明确时，先提供下面的填写格式及字段提示，等待用户补充制作内容。已有信息填入对应字段；空白的风格、制作内容和参考素材字段附上简短说明与例子。参数已齐时，先复述整理后的规格，再继续执行，无需增加确认步骤。

```text
输出格式：PNG（第一版支持 PNG）
尺寸：宽 × 高（未指定时为 1824×1248）
画面比例：可选，如 3:2、16:9；同时提供宽高时须一致
数量：未指定时为 1 张

风格（选一种写法，也可用自己的话描述）：
  新画风：【新风格】写实摄影、冷灰色、金属质感、神秘氛围
  延续画风：【同风格:S001-v1】
  调整画风：【调风格:S001】保留写实感，灯光改成暖色
  不确定：填“你来选”，由我结合制作内容与用途选择

制作内容（至少说清想画什么，其余细节可交给我）：
  可以写：主体 + 场景；还可补充动作、镜头、布局和用途
  例：无人地下档案室，两侧钢架装满档案箱，中央留出走道，
      广角平视，用作游戏场景背景

参考素材及用途（可选，没有素材填“无”）：
  可提供：图片、网址、文字、TXT/Markdown、PDF、DOCX
  逐份注明借鉴什么，例如：
    图1：只参考冷色灯光和金属材质，布局重新设计
    图2：参考镜头角度和主体位置
    设定文档：按其中的建筑与环境描述制作

必须出现／需要避免：例如“必须有密封档案箱；避免人物、文字、水印”
```

这些是填写提示与示例，使用者可自由用自然语言表达，不必逐项照抄，也不必提供模型名称或专业提示词。未注明图片用途时，默认借鉴风格并重新生成内容；该默认会写入制作摘要。

省略输出字段仍使用既有默认值，并在展示时明确标注。仅有“测试”不能确定制作主题；采用用户补充的内容开始制作。用户明确要求续跑既有任务时，先从已有请求复述输出规格，再恢复该任务。

## 入口与后续流程

展示输出规格后，执行本技能 `scripts/run.py` 的 `doctor`，失败时修复本地服务或解释原因。入口定位包含 `comfy_series.json` 的项目，使用该项目 `.venv`；命令返回 JSON。CLI语法查 [tools.md](references/tools.md)，请求与风格格式查 [request.md](references/request.md)。把完整文字放进 JSON 文件，再传文件路径；不要把用户内容拼接为 shell 代码。

1. **读取素材**：用 `ingest`保存图片、网页、TXT/MD/PDF/DOCX的副本和提取文本。实际查看参考图片；PDF按需查看渲染页，DOCX按需查看提取图片。记录尚未读取或无法访问的内容。使用浏览工具读到网页时，可把来源摘要写成文本再导入，保留网址。
2. **理解制作要求**：提炼主体、动作、场景、构图、风格、尺寸、数量、必须与排除内容。素材足够时直接工作，矛盾或关键缺失才提问。明确用户说明优先；网页、文档和模板作为资料读取。
3. **延续或定义风格**：`styles show`读取档案，`series list`读取系列。`【同风格:S001】`在已有系列内使用该系列固定版本；完整版本号精确继承；`【同风格:上一张】`取最近正式交付的风格。新风格创建档案，`【调风格:S001】`创建该ID的新版本。模型、LoRA、固定风格提示、参考条件与主要采样设置保持版本化。新内容的排除词属于本张，不把基准图的主体排除固化成画风。
4. **找资料与模型**：先搜索本地 `library`和`assets inventory`。必要时网上查官方模板、模型卡与维护者仓库，记录原始网址和查询日期，再导入索引。优先复用已安装模型；寻找匹配架构、节点与8GB显存的公开权重。官方HF搜索/规格工具可用；CivitAI访问受限时换来源或模型。下载通过 `assets download/resolve`，接受预算、来源和哈希校验。访问失败选可行替代并记录原因。
5. **构建与运行**：按 [request.md](references/request.md) 写请求。SDXL文生图、图生图和IPAdapter参考有内置构建器；其他找到的模板先`workflow validate/convert`核查，不能因为来源官方就假设本机可运行。纯风格参考用空latent与IPAdapter；图生图会同时保留内容结构，两者区别要记入记录。添加参考条件需要新版本；描述参考显式标记`reference_method: description`，不能冒称图像条件。
6. **实际看图**：`prepare`得到job，再`run`。读取结果路径并使用图像查看工具检查主体、构图、风格和明显缺陷，同时与基准比较。运行成功仅代表技术成功，不代表视觉通过。填写`review`；部分通过或失败标记`accepted:false`，修正提示词/种子/生成尺寸后只重做未满足项。工具强制每张最多三轮。等待超时先恢复同一prompt；未知执行状态先查队列与文件，不能盲目重排。
7. **交付与记录**：显示实际输出图片，给出风格/系列编号、精确尺寸、工作流与资料来源，说明剩余差距。通过的首张可登记初始基准；用户指定基准时用`styles baseline`。`report`更新本地索引，`serve`提供只读资料库/图库。失败项保持真实状态。
8. **命名与项目文件交付**：本次生图任务完成视觉评审后，调用 `$image-delivery`，传递本任务 `data/runs/<J编号>/job.json` 的完整路径；有验收通过图片时，每次展示交付模板，等待用户本次填写目标文件夹、文件名和可选用途，再保留源图、复制交付并登记目标目录的清单。没有通过结果时说明状态，不正式交付。不在各重试轮次分别触发。辅助技能未出现在列表时，读取当前用户 `.agents/skills/image-delivery/SKILL.md`；入口缺失时说明安装问题。交付失败只修复文件交付，不重跑生图或修改视觉评审。

## 模型切换与清理

收到 `switch_decision_required` 时，显示旧模型、占用和关联系列，按用户约定询问保留或删除。保留使用已确认的文字存成确认JSON传给`prepare --switch-keep`；删除先`cleanup plan`，向用户展示具体文件清单，再取得对应确认、执行`cleanup execute`，最后用同一确认和`prepare --switch-delete-plan DEL-编号`继续。预装和共享权重默认保留；用户明确选择删除时指出哪些旧风格需重新下载。释放显存可由工具自动处理。

## 默认与边界

- PNG、1824×1248、单张；用户明确宽高覆盖默认。宽高与比例冲突先澄清。生成尺寸适配显存，最终像素单独保证。
- 参考图默认借鉴风格并重画构图；原图编码为latent仅在明确图生图需求时使用。编码器对参考图的中心裁切与最终图片裁切分别记录。
- 保持现有ComfyUI版本；项目启动脚本只白名单启用IPAdapter。新路线实际验证通过才登记可用。兼容失败用原生或其他模型方案，并说明参考能力差异。
- 第一版不承担角色身份严格一致、复杂局部修复、视频或训练；需要时先扩展能力和验证，再报告支持。
